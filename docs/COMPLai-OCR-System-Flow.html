COMPLai · OCR & signboard compliance — flowchart & end-to-end logic

This document describes what the stack does: React client → FastAPI backend → Google Cloud Vision → SignboardGeometryAgent (OpenCV) → UniversalComplianceEngine (COMPLai) → optional governance heuristics & audit storage.

1. System context

The product reads signboard images (after optional perspective correction in the browser), extracts text and structure with Document Text Detection, measures where ink is in a canonical rectified frame, and scores whether a state / UT’s mandatory script (e.g. Kannada, Marathi) meets a minimum threshed-ink share when the user has chosen that jurisdiction. Vision is not given language hints in production — script is auto-detected. The state code only drives COMPLai rules, not the OCR call.

3. What happens in /api/ocr (order of operations)

  1. Upload — Raw bytes, MIME, filename; may transcode (AVIF/HEIC → PNG) for Vision.
  2. Raster preprocess (vision_preprocess.py / image_prep.py): optional high-key CLAHE (LAB), then light-aware HSV “signboard pop”; optional VISION_OCR_PREBINARIZE with smart path for washed images.
  3. Google Vision — ImageContext() with no language_hints. Features: Document Text Detection + Logo Detection.
  4. Page / block / word tree → full text, per-block bounds, language hints from Vision on property.detected_languages (per block; not from hints).
  5. Threshed ink — SignboardGeometryAgent uses the same image (processed buffer) and the Vision response: homography to 1000×600, per-block or per-word ink via adaptive threshold, aggregate language_ratios, primary_ratio, per_block_threshed_board_pct.
  6. Location — Form state_code and/or latitude+longitude → optional reverse_geocode to infer state.
  7. COMPLai — UniversalComplianceEngine (in compliance_rules.py) maps state_code to primary ISO, min_primary_area_pct → min_local_lang_pct for evaluate_compliance. If no state, compliance = PENDING — STATE REQUIRED.
  8. Governance (optional) — governance_evaluate.py merges public-policy-style checks (e.g. KA layout hints) on top of the threshed result message.
  9. Persist — AuditRecord in SQLite/Postgres, image in local/S3, JSON snapshot for replay.

4. SignboardGeometryAgent — internal logic (conceptual)

Code: backend/signboard_agent.py — if Vision says und, the agent can infer script from Unicode in block text via indic_script_infer.py (for ink bucketing, not a separate OCR model).

5. COMPLai — UniversalComplianceEngine & evaluate_compliance

STATE_RULES (per state/UT): primary_iso_code, min_primary_area_pct (0–1), font_ratio_required (e.g. Maharashtra: policy note only in details — the flat test is still threshed-ink share).

flowchart TB S[state_code from user or geo] --> N[Normalize codes TS to TG UK to UT] N --> L{In STATE_RULES?} L -->|no| PEND[pending or uncertain] L -->|yes| R[Build location_rules] R --> M{Has threshed ratios?} M -->|no| U[uncertain] M -->|yes| V[Remap with verified text json] V --> T[Test min share or mono exemption] T --> F[pass or fail]

Review / PUT /api/audit/{id}: verified_text_json updates block text and verified language. recompute_geometry_after_verified_overrides re-buckets threshed mass by user language so e.g. Kannada share is counted under kn for Karnataka.

6. Batch COCO report script (offline evaluation)

backend/scripts/coco_batch_ocr.py — reads a Roboflow zip (train/ test/ valid images), runs the same preprocess + Vision (doc text only) + SignboardGeometryAgent as the API, writes backend/data/coco_batch_ocr_report.json. HTML: scripts/coco_batch_report_to_html.py → docs/.
