This document describes the persistence layer, the OCR API contract (OcrResult and related types), and how they relate. The runtime source of truth is the Pydantic models in backend/main.py and backend/db_models.py.

1. Database

Engine: DATABASE_URL (PostgreSQL) or default sqlite:///./ocr_audit.db (backend/database.py).

1.1 Table audit_records

Column Type Notes
idUUID, PKDefault uuid.uuid4()
user_idVARCHAR(256), nullable, indexedOptional client id (e.g. from localStorage)
image_urlTEXT, not nullPublic URL of stored upload (local /files/... or S3/CDN)
raw_ocr_jsonJSON / JSONB, not nullFull OcrResult as returned by POST /api/ocr (see §2)
verified_text_jsonJSON / JSONB, nullableMap of block index (string) → user-corrected text
location_dataJSON / JSONB, nullablestate_code, city, latitude, longitude, geocoded, etc.
compliance_statusVARCHAR(32), not nullPENDING | PASS | FAIL | UNCERTAIN (ComplianceStatus)
location_state_codeVARCHAR(8), nullable, indexedDenormalized for reporting
threshed_dominant_langVARCHAR(16), nullableBCP-47 (dominant threshed script)
threshed_l1_code … threshed_l3_codeVARCHAR(8), nullableTop 3 threshed languages by share
threshed_l1_ratio … threshed_l3_ratioDOUBLE / REAL, nullableRatios 0–1 for those ranks
created_attimestamptz, not nullServer default now()

init_db() runs Base.metadata.create_all and alters existing databases to add columns from _ensure_audit_columns when missing.

Entity (no foreign keys to other tables): single audit store; files live on disk or S3.

audit_records ├── id (uuid, PK) ├── user_id, image_url ├── raw_ocr_json, verified_text_json, location_data ├── compliance_status, location_state_code ├── threshed_dominant_lang ├── threshed_l1_code/ratio … l3_code/ratio └── created_at

2. API model: OcrResult and raw_ocr_json

OcrResult is the JSON of POST /api/ocr and PUT /api/audit/{id}. The same object is stored in raw_ocr_json (server may add audit_id and refresh compliance/location on update).

2.1 Top-level fields

FieldTypeDescription
textstringFull block text (Vision)
image_width, image_heightintPixel dimensions (Vision first page)
languagesLanguageHint[]Page-level hints
blocksTextBlock[]Per-region text, boxes, words, optional translation
logosLogoResult[]Logo detections

is_pdf_ocrboolTrue when input was PDF
audit_idstring | nullUUID when a row was saved
resolved_locationobject | nullstate_code, city, state_name, latitude, longitude
verified_text_jsonobject | nullBlock-index → corrections (when reloaded from DB)
image_metadataobject | nullFile + EXIF + dimensions (§2.3)

2.2 Nested DTOs (summary)

  • LanguageHint: code (BCP-47), confidence (0–1)
  • BoundingBox: x, y, w, h
  • NormArea: x_pct, y_pct, w_pct, h_pct, area_pct (0–100), optional threshed_area_pct
  • VerifiedWord: text, confidence, is_doubtful
  • TextBlock: text, bounds, norm, languages, words, translated_text (optional)
  • LogoResult, GstinFinding, ComplianceInfo, SignboardGeometrySummary — as implemented in Pydantic (main.py)

2.3 image_metadata

KeyContent

rasterNon-PDF: format, dimensions, color_mode, optional exif or error. PDF: short note
visionwidth, height
pdf{ "is_pdf": true } when applicable

3. Other API request/response bodies

EndpointBody / model
POST /api/ocrmultipart: file, optional user_id, state_code, latitude, longitude
PUT /api/audit/{audit_id}JSON AuditUpdate (user_id, location, state_code, city, verified_text_json)
POST /api/translateJSON: texts[], optional languages[]
POST /api/suggest-cornersmultipart: file, optional state_code → SuggestCornersResult (corners 4×[x,y], method, dimensions)

4. Frontend

Types in frontend/src/ocrTypes.ts mirror §2; no second canonical schema.

5. File storage (not in SQL)

  • Local: LOCAL_STORAGE_DIR or backend/data/uploads/; URL PUBLIC_BASE_URL + /files/{uuid}{ext}
  • S3: if S3_BUCKET is set, same key pattern; S3_PUBLIC_BASE_URL when set

image_url always points at the stored object.
